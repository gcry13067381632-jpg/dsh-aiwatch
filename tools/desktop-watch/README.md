# desktop-watch · 桌面操作轨迹监听（v2.1）

让 AI 知道「你刚才在电脑上动了哪些文件」，省掉复制路径那一步。

## 用法

```powershell
# 监听桌面（默认），输出到 watch-log
node .\watch-desktop.mjs

# 换目录 / 换输出位置 / 提高真人判定窗口（毫秒）
node .\watch-desktop.mjs --dir "D:\某个文件夹" --out "D:\newwenjianjia\aiwork\鲸鱼娘\watch-log" --human-ms 2500
```

停止：结束进程即可（Ctrl+C 或 kill 掉 node 进程）。

## 输出

- `watch-log\trail.txt` —— 人话轨迹，AI 直接读这个
  ```
  [13:19:54] 新建文件夹 _dsh_watch_test · 真人(高) · 前台:msedge · 距键鼠0.4s · 置信0.62
  [13:20:33] 改名/移动 a.txt → b.txt · 真人(高) · ...
  ```
- `watch-log\events.jsonl` —— 每条一个 JSON，字段：ts/iso/kind/name/abs/size/idle/fg/conf/verdict

## 判定规则（v2.1）

1. **键鼠活跃**：每 400ms 采一次「距上次键鼠输入多久」（`GetLastInputInfo`）+ 前台窗口进程名/标题。
   - 距输入 < 1.5s → +0.5；< 2.5s → +0.35；< 10s → +0.12；更久 → +0.03
   - 前台是资源管理器类（explorer/TotalCmd…）→ +0.25；是编辑器/终端/浏览器 → +0.12
   - 命中噪音规则（`~$`、`.tmp`、`.crdownload`、`Thumbs.db`…）→ −0.35
   - 结果：≥0.6 真人(高)｜≥0.35 真人(中)｜其余 存疑(程序?)
2. **AI/程序打标**：写 `watch-log\ai-hold.json` 为 `{"until": 毫秒时间戳}`，该时刻前的事件一律判「AI/程序(已打标)」，不再受键鼠活跃影响。
3. 降噪：目录自身的「修改」丢弃；新建/改名后 1.2s 内的「修改」合并；同路径同类型 400ms 去抖；2.5s 内「消失 + 出现且大小相符」合并为「改名/移动」。

## 已知局限（下一步要解决）

- 拿不到写文件的 PID（`fs.watch` 不给），所以「程序 vs 真人」目前靠键鼠/前台/打标三个信号推断。
- 你在跟 AI 聊天时键鼠恰好活跃，此刻 AI 动文件会被误判成真人 —— 靠 `ai-hold.json` 打标解决（dsh 插件里会自动打）。
- 全量事件偏碎，多文件批量操作还没聚合成「一次操作」。

## 后续规划

- 包成 dsh 插件：悬浮球开关 + 面板看轨迹 + 事件静默写进会话（不唤醒）
- 与 dsh 工具层联动：AI 每次动文件前自动写 `ai-hold.json` 打标

## v4：假修改过滤 + 噪音文件不进轨迹（2026-10-04）

现象（主人当场抓到的）：在桌面上按 F5 刷新一下，就被记成 12 个「修改 .lnk / .docx / .xlsx」。

实测证据（刷新那一秒）：

    DeepSeek Harness.lnk  最后写入=10-03 20:38:13  最后访问=10-04 16:05:28
    度盘目录.docx          最后写入=04-23 21:14:39  最后访问=10-04 16:05:28
    新建 XLSX 工作表.xlsx  最后写入=10-13 19:03:37  最后访问=10-04 16:05:28

即：**内容一个字节都没改**，只是"最后访问时间"被更新了 —— 刷新桌面时资源管理器要重建图标，
得去解析 .lnk 的目标、读 Office 文档拿缩略图；NTFS 顺手更新访问时间，而 Windows 的目录变更
通知把这种变动也报给了 fs.watch。所以它既不是真人编辑，也不是 AI 干的，纯属"被读了一下"。

v4 规则：
1. 「修改」必须**内容真的变了**才算：比对 `大小 + 最后写入时间(mtime)`，两者都没变 → 静默丢弃，
   只在 events.jsonl 记一条 `noop:true, reason:"内容未变(仅被读取/刷新)"`。
2. 启动时先给监听目录拍一份基线（路径 → 大小:mtime，深度 ≤4、上限 20000 项），用于上面第 1 条比对。
3. 噪音文件（`~$`、`Thumbs.db`、`desktop.ini`、`.tmp/.part/.crdownload`）不再进 trail.txt
   （只留 events.jsonl 的 noop 记录），免得白占 AI 的 token。
4. 计数器每 20 条汇总一行日志：`（已静默忽略 N 次「只是被读取/刷新」的假修改、M 次噪音文件）`。

自测（临时目录，非桌面）：只读+SetLastAccessTime → trail 0 行、jsonl 1 条 noop；
真追加内容 → trail 正常 1 行。

生效方式：监听脚本是独立进程，**插件页把 dsh-aiwatch 关掉再打开**即可用新脚本重启监听（不用重启 dsh）。

## v5：文本文件编辑内容（差异）也入站（2026-10-04）

主人要的：在目标文件夹里用编辑器改文本类文件（txt 不限，md/json/js/py/ps1/yaml/csv… 都算），
不光记「修改 某文件」，还要把**改了哪几行**送进上下文。

轨迹里的样子（差异行缩进 2 空格、跟在轨迹行下面，算同一条）：

    [16:11:40] 修改 笔记.txt
      - 第二行
      + 第二行改过了
      + 新加的一行

判定文本文件的条件：扩展名在白名单里（或没有扩展名），文件 ≤1MB，**没有 NUL 字节**（不是二进制），
UTF-8 能干净解码（不行再试 GBK）。每次真实修改都会 diff：行级 LCS，最多 24 行、每行最多 160 字符，
超了补一行「…（还有 N 行变更已省略）」；文件太大（行数乘积 >40 万）就退化成"第 N 行起 X 行 → Y 行"的摘要。

配套改动（插件 dsh-aiwatch v0.1.4）：注入改为**按条目取**——一条 = 一行 `[时间]` 开头 + 后面缩进的差异行，
取尾部时按条目切，绝不把差异块拦腰截断；尾巴上没写完的一条留到下一轮。`--diff 0` 可关掉差异功能。

## v6：.docx（Word）正文也纳入差异检测（2026-10-04）

主人问"doc 文件呢，可以只检测文本吗"。答：**.docx / .docm 可以，而且抽的就是纯正文文字**；
老式 **.doc（97-2003 的 OLE 二进制）不支持**（要调 Word/WPS 转换，太重）；.pdf/.xlsx/.pptx 暂不支持。

原理：.docx 本质是个 zip，正文在 `word/document.xml`。脚本自己解 zip —— 从尾部找 End of Central Directory
（0x06054b50）顺中央目录找到该条目（method 8 用 `zlib.inflateRawSync`，method 0 直接取），
再删掉所有 XML 标签、`</w:p>` 当换行、`<w:tab/>` 当制表符、反转义实体，得到按段落分行纯文字。
之后和 txt 完全一样走行级差异 —— Word 里改了哪几段，AI 一样看得到。

    上限：压缩包 ≤12MB、抽出正文 ≤20 万字符（超了截断并注明）；样式/图片/修订记录一律不管。
    安全：任何解压/解析失败都 fail-soft，退化成"只记一行 修改 xxx.docx"，不会崩。

实测（临时目录造的 docx，改两段）：

    [16:18:25] 修改 说明.docx
      - 第一段
      - 第二段
      + 第二段改过了
      + 新加的一段

顺手修掉本地诊断日志里判定字段重复打印的小毛病（`存疑(程序?) · 存疑(程序?)`）。

## v7：编辑器「写 tmp 再改名覆盖」的保存也认出来（2026-10-04）

主人实测：在桌面用 Word/WPS 改了 docx，轨迹里只有一句
 `[16:22:21] 改名/移动 新建 DOCX 文档~7B1A3.tmp → 新建 DOCX 文档.docx`，**没有正文差异**。

原因：编辑器保存不是就地写，而是先写 `xxx~7B1A3.tmp`、再改名覆盖目标（顺带还有 `~$xxx.docx` 锁文件）。
fs.watch 报出来是「删除 .tmp + 新建 目标名」，v6 把它配成了"改名/移动"，而差异只在「修改」时才算 → 改动白丢。

v7 三处修：
1. **保存覆盖识别**：该配对里如果「旧名字是临时/噪音文件」或「新名字本来就有内容快照」，
   就按「修改」处理并算差异，不再显示成"改名/移动"。
2. **删除延迟确认（2.5 秒）**：删除的轨迹行不再立刻写，等 2.5 秒；期间同名文件又出现就当没删过
   （保存/改名都是这个模式）。真删除照旧会记，只是晚 2.5 秒。
3. **删除不再清空内容快照**：保存覆盖要拿旧内容比差异，快照丢了就没法补（多留一点内存换差异）。

实测三种情况（临时目录）：

    [16:24:48] 修改 文档.docx          ← Word 式保存（tmp→改名覆盖），差异 4 行给全
      - 旧的第一段
      - 旧的第二段
      + 新的第一段
      + 新加的第二段
    [16:24:51] 改名/移动 aa.txt → bb.txt   ← 真改名，照旧
    [16:24:54] 新建 cc.txt                  ← 真新建
    [16:24:58] 删除 cc.txt                  ← 真删除（延迟 2.5 秒确认）

生效：监听脚本是独立进程，插件页把 dsh-aiwatch 关掉再打开即可（不用重启 dsh）。

## v8：把"现在前台是谁"落盘（给聚合注入当触发源）（2026-10-04）

每当前台窗口变化/有输入（以及每 10 秒心跳），监听脚本除了自己用，还顺手写一份
`<输出目录>\fg-state.json`：

    {"fg":"msedge","title":"…… — DeepSeek Harness - 个人 - Microsoft Edge","idleMs":3718,"ts":…,"seenAt":…}

用途：插件 dsh-aiwatch v0.1.5 的**聚合注入**靠它判断"主人切回 dsh 窗口了没有"，
从而把攒着的轨迹一次性发出（见插件 README 的"聚合注入"）。实测抓到标题里带 `DeepSeek Harness`，
所以按 进程名/标题 里的 `deepseek / harness / dsh / 鲸鱼娘` 匹配是能命中的。
